# dsh-models-helper · 模型助手

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）插件。它把内置模型供应商克隆为**自定义供应商**，让模型列表、模型参数和价格跟随 [models.dev](https://models.dev) 与 OpenRouter 的公开数据同步（价格在你手动克隆或检查更新时刷新），不用再逐个手填；同时估算每一轮对话和每个会话的花费。

*A DeepSeek Harness plugin that clones built-in model providers into custom providers whose model lists, parameters and prices stay in sync with models.dev and OpenRouter, and estimates per-turn and per-session cost.*

> **项目状态：M1 开发中（冒烟验证阶段）。** 技术验证（M0）已完成；克隆、绑定、检查更新、字段锁与默认模型切换已实现，正在运行中的 DSH 上验证。价格表与花费估算（M2）尚未实现。进度见 [ROADMAP.md](ROADMAP.md)。

## 它解决什么问题

DSH 内置供应商（如 `opencode-go`、`openrouter`）的模型目录随 DSH 版本打包，网关上线了新模型，往往要等下一次 DSH 发版才能用到。

改用指向同一网关的自定义供应商可以立刻用上新模型，但每个模型的参数都要手填：上下文窗口、最大输出、输入类型、推理等级、请求兼容性开关（compat），全部从零开始。很多网关同时提供多种协议（例如 opencode-go 同时有 Chat Completions、Responses、Anthropic Messages 和 Gemini 四种），手工维护的成本更高。

模型助手把这些参数从公开的数据源和 DSH 自带的模型目录里取出来，替你写好，并在数据源更新后给出差异，由你确认后再应用。

## 功能

| 功能 | 状态 |
|---|---|
| **克隆内置供应商**：一键生成自定义供应商，把原 key 复制到新路由自己的凭据引用（此后互不影响），混用多种协议时按协议拆成几条路由，参数自动补全 | 已实现（M1，验证中） |
| **绑定已有的自定义供应商**：为手工建的供应商指定更新来源，补全缺失参数 | 已实现（M1，验证中） |
| **检查更新**：对比数据源和当前配置，按"新增 / 候选 / 字段更新 / 冲突 / 来源已下架"分组列出差异，勾选后应用；自动识别并保留你手改过的值；每次检查都强制联网获取最新数据，失败时回退缓存并标注数据获取时间；支持字段锁定 | 已实现（M1，验证中） |
| **价格表**：每个模型的输入、输出、缓存读、缓存写单价（美元 / 百万 token），可手动覆盖；价格随克隆与检查更新刷新到本地，改价后估算立即重算 | 计划中（M2） |
| **花费估算**：每一轮末尾显示本轮花费；会话标题栏显示会话累计，含子智能体 | 计划中（M2） |
| **智能体工具**：让智能体查看状态和差异，经你审批后应用 | 计划中（M3） |

## 工作原理

- **数据源**：models.dev（pi-ai 内置目录的上游）和 OpenRouter 官方 `/api/v1/models`，提供模型列表、上下文/输出上限、输入模态、推理档位、价格，以及每个模型使用的协议。
- **模板**：DSH 自带的 pi-ai 模型目录。数据源不提供的请求兼容性开关和推理档位写法从这里取；新模型沿用同系列模型的设置，并在差异中标注为"推断"。
- **价格**：单价只在你点击「克隆」或「检查更新」时从数据源取回并写入本地价格快照；界面和花费估算按本地价格表实时计算，渲染时不联网。
- **写入**：只通过 DSH 的设置接口写 `llm-pi-ai`（模型供应商）和本插件自己的配置，与「设置 → 模型」页面走同一条路径，并带版本号，避免覆盖并发修改。每次写入都要你在差异面板里确认。

详细规则见 [docs/DESIGN.md](docs/DESIGN.md)。

## 环境要求

- DeepSeek Harness **0.2.2-rc.2**，使用 Web 界面。其他版本尚未验证。
- DSH 所在机器需要能访问 `https://models.dev` 和 `https://openrouter.ai`。

## 安装

**从本地目录安装**（目前唯一的方式）：

1. 克隆本仓库。仓库已提交构建产物 `lib/`，安装时不需要构建。
2. 在 DSH 的 **插件** 页面选择 **添加插件**，指定本仓库所在目录。也可以让 DSH 的智能体执行 `plugin_manager install_bundle`，把目录的绝对路径作为 target。
3. 刷新页面，打开「设置 → 模型」。

发布到 npm 后也可以从插件市场安装（计划中）。

## 使用

**当前（M1）**：

1. 内置供应商卡片 →「克隆为自定义供应商」：向导会拉取来源数据，按协议分组预填路由 id 与显示名，可搜索/勾选模型、设置「自动纳入新模型」，确认后生成自定义供应商：原 key 会复制一份到这个路由自己的凭据引用（`<ROUTE>_API_KEY`），并提示切换默认模型。
2. 已有的自定义供应商卡片 →「绑定更新来源」：选择更新来源与模板，绑定后立即给出首次差异；默认把当前值当作你的手改，来源不同项按冲突处理。这个绑定只用于检查更新，解除不会删除路由、模型或 key。
3. 已绑定的卡片 →「检查更新」：每次都会联网获取最新数据并刷新本地价格快照；失败时回退最近缓存并在面板标注数据获取时间。差异按新增 / 候选 / 字段更新 / 冲突 / 来源已下架分组，字段锁定的项不参与检查。卡片上可随时切换「自动纳入新模型」；在模型页手动新增的模型，检查更新会补全它未设置的字段，已设置的参数默认保留为冲突。
4. 页脚汇总所有绑定，可「全部检查更新」；来源缓存的状态与刷新也在页脚（刷新只更新缓存，不改价格快照）。

> **注意**：克隆出的供应商拥有自己的 API key 引用，删除或重新填写原内置供应商的 key 不再影响它。早期版本创建的克隆可能仍与原供应商共用引用；卡片上会提示并提供「创建独立密钥」修复。

## 数据与隐私

- 插件只请求上面两个公开接口，**不携带任何 API key**。
- 克隆时为了独立凭据，会把原路由当前的 key 复制到新路由自己的引用（存在 DSH 凭据库中）；不克隆则不复制任何密钥。
- **只在显式动作时联网**：点击「克隆」「检查更新」（含「全部检查更新」）或页脚的「刷新」才会发起请求；每次检查更新都会重新请求最新数据。页面渲染与花费估算只读本地数据，不联网。
- 元数据缓存在 `<DSH_HOME>/integrations/dsh-models-helper/cache/`，价格快照在数据目录下；检查更新失败时回退最近缓存，并在界面标注数据获取时间。这些本地数据可以随时删除。
- 不读取对话内容；花费估算（M2）只读取会话日志里记录的 token 用量，并按本地价格快照计算。

## 卸载

在插件管理中移除 `dsh-models-helper`。克隆出的自定义供应商是普通的 `llm-pi-ai` 配置，卸载后仍可继续使用和手工编辑；不再需要时可以删除 `<DSH_HOME>/integrations/dsh-models-helper/` 目录。
